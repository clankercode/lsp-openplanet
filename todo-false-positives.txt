# Angelscript LSP false positives
# (LSP reports errors that the game-side compiler accepts cleanly)

## 2026-04-20, tm-draw-tests

### Case 1: Named argument resolves to wrong parameter when skipping positional args [FIXED: named args match by parameter name, skipping defaulted params]
Plugin source (src/GraphTab.as:261, 266, 271, 276):
    void AddIndentedTooltip(const string &in msg, bool pushFont = false, float w = -1.0) { ... }

    AddIndentedTooltip("...", w: 20.0);

LSP reports:
    src/GraphTab.as:261:132: error: argument 2 of `AddIndentedTooltip`: expected `bool`, got `float`

Reality:
    Game-side Angelscript compiler accepts `w: 20.0` as a named argument
    for the third parameter and compiles cleanly.

The LSP appears to be binding named arguments positionally — it maps the
named arg to the next unfilled slot (argument 2, `pushFont: bool`) instead
of matching by parameter name. Named arguments should skip over intermediate
defaulted parameters.

## 2026-08-12, tm-better-totd (LSP FPs vs game)

Remote-build on Openplanet **1.29.5**: game failed only on `Text::Join` (5×).
LSP previously reported 22 errors; after fixes → 4 empty-catch (B002) under
`#if DEPENDENCY_*` optional-dep defines.

### Fixed false positives

1. **startnew(BareFunc)** — bare function idents typed as `Named(funcName)` and
   ArgTypeMismatch vs `CoroutineFunc`. Fix: functions-as-values → `Funcdef`,
   convertible to CoroutineFunc* params.
2. **Global vars as args** (`vec4 overviewTableRowBg`, `UI::Font@ g_BoldFont`,
   `Json::Value@ meta`) — symbol extractor stored empty `type_name` for
   top-level VarDecl/Property; Ident collapsed to `Named(varName)`. Fix: lift
   type text + `lookup_global_value_type`.
3. **array.InsertLast / Find** — external overloads use unsubstituted `T`;
   ArgTypeMismatch `expected T, got LazyMap`. Fix: skip unsubstituted generic
   / `?` placeholders in external arg checks (`tostring` too).

### Not FPs / deferred

- Empty `catch {}` under optional deps: B002 true positives when defines on.
- `Text::Join`: real game error on 1.29.5; plugin targets ~1.29.12. LSP still
  silent (FN under NamespaceAccess). Version-ranged API rules: GH #18.

## 2026-08-22, tm-draw-tests (LSP FP vs game 1.29.5)

### Case: single-arg value-type constructor is not treated as an implicit conversion [FIXED 2026-08-22: GH #54, d1090f3 — typedb-driven ctor conversions; fixture 54-ctor-implicit-conversion]
Plugin source (src/DipsItem_Skel.as:112):
    mat3 rot = charRot * hatRot;
    return mat4::Translate(worldPos) * mat4::Inverse(rot);

LSP reports:
    src/DipsItem_Skel.as:112:58: error: argument 1 of `Inverse`: expected `mat4`, got `mat3`

Reality:
    Game compiles the whole plugin with zero errors — no diagnostic at all on
    DipsItem_Skel.as (file confirmed staged and compiled; no `#if` guards).

Why:
    OpenplanetCore.json registers `mat4` with a single-argument construct
    behavior `mat4(const mat3&in)` (behaviors[].type == 0, i.e.
    asBEHAVE_CONSTRUCT). AngelScript uses such single-arg value-type
    constructors as an implicit conversion when matching call arguments, so
    `mat4::Inverse(mat3)` resolves via `mat4(const mat3&in)`.
    (`mat3` symmetrically has `mat3(const mat4&in)`.)

Fix direction:
    When arg-type matching fails on an external/builtin call, allow the
    conversion if the *parameter* type is a value type in the typedb with a
    single-argument construct behavior accepting the argument type. Applies to
    every such pair in the typedb, not just mat3/mat4 (e.g. iso3/mat3,
    iso4/mat4, vec* combinations).
